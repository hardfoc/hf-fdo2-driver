Split exchange — send now, parse the reply later

For a caller that serves other devices while the probe measures (~150 ms): SendMeasure writes the command and returns; when the transport reports a complete line, TryReadReplyLine takes it without waiting and ParseMoxyLine / ParseMrawLine decode it. The caller owns the reply timeout. Same wire protocol as MeasureMoxy.

◆ SetCrcRequired()

template<typename UartT >
void fdo2::Driver< UartT >::SetCrcRequired ( bool  required)
inlinenoexcept

Require the #CRCE 1 checksum on every reply (data sheet §4.2).

A reply that carries the suffix is always verified. With this set, a reply without it is rejected too (CrcMismatch), so a corrupted : cannot hide a bad reply. Set it only for a module whose CRC is enabled; the driver never sends #CRCE.

◆ SetSlowCommandTimeoutMs()

template<typename UartT >
void fdo2::Driver< UartT >::SetSlowCommandTimeoutMs ( uint32_t  ms)
inlinenoexcept

Timeout for commands the module answers only after a long task (default 12000 ms).

Data sheet §4.1: the echo comes "after completion of the requested task". Used by FlashLogo (#LOGO: the LED flashes for about 1 s, §4.3); also sized for #CALO / #CAHI, which take up to 10 s. A port that returns at the CR still returns as soon as the echo arrives.
